Qualification scorecard

Problem severity

  • Agents represent multiple clients/programs/locations
  • Static knowledge/search creates measurable friction
  • Wrong answers or promises create real cost/risk

Operational readiness

  • Named sponsor and rule owner
  • Source material can be provided
  • Workflow can be bounded
  • Users can be identified

Commercial readiness

  • Real decision date
  • Buyer can pay for a pilot
  • A continued use case exists if the pilot works
  • Security/procurement is navigable at this stage

Discovery questions

Current work

  • How many client rule sets can one agent touch?
  • Where do agents look when they do not know?
  • Which decisions create the most supervisor questions?
  • What changes frequently?

Cost / consequence

  • What happens when the wrong rule is applied?
  • Where does search time show up operationally?
  • How long until a new agent is trusted on an account?
  • What limits adding new clients/programs?

Buying / pilot

  • Who owns the problem?
  • Who owns the rules?
  • What result would justify continuing?
  • What would kill the pilot?

Demo structure

Do not tour every feature. Prove the interaction model against the buyer’s pain.

1

Set the problem

One workforce, many client-specific rules, and a human forced to reconstruct context while the customer waits.

2

Show the context shift

Switch client/account and show how the rule environment changes.

3

Show the operational payoff

Request → rule state → approved wording → next action → provenance/testability.

Objection framework

ObjectionResponse direction
“We already have a knowledge base.”A knowledge base makes information available. Agent First is testing whether the system can resolve the current context into the relevant rule and next action without forcing the agent to search and interpret.
“Why not just train agents better?”Training remains important. The hypothesis is that memory should not be the only control layer when rules change and agents represent multiple clients.
“Is this replacing agents?”No. The product is designed to keep the human customer-facing while shifting context reconstruction and rule application into the system.
“Is this production-ready for regulated data?”Only for scopes that have passed the relevant legal/security/data boundary. Do not claim broader readiness.
“Can you prove ROI?”Not yet as a generalized claim. The paid pilot exists to establish a measured baseline and result before ROI language is published.

Follow-up cadence

After discovery

Same-day summary of the problem, proposed pilot question, open requirements, and next decision.

After demo

Send the specific interaction demonstrated, the Deal Room, pilot criteria, and one clear next step.

Stalled opportunity

Do not spam. Re-engage only with a relevant trigger: timing change, new proof, new buyer, new problem, or explicit agreed follow-up date.

Win / loss and hiring rules

Track losses by reason: no problem, no urgency, no sponsor, no budget, security/procurement blocker, no baseline, custom-work mismatch, competitor/status quo, timing, or product gap. Do not hire a sales rep to discover the sales motion. Hire after founder-led sales has repeated enough that lead volume/follow-up capacity—not lack of product-market understanding—is the bottleneck.
