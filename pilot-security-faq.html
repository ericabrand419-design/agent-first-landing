Pilot diligence · current-state overview

Clear boundaries before your rules enter the system.

This page describes the current Agent First pilot environment: what we need, what we do not need, how approved rules are governed, how evaluator access works, and which controls are still early-stage rather than certified.

Current controls

What exists today

LIVE

Invited account access

Private evaluator access uses invitation activation, email + password sign-in, password hashing, time-limited server sessions, and role-aware views.

LIVE

Approved-rule authority

Client-provided approved rules remain the authority. Agent First is designed to surface them; it is not authorized to create policy on the client’s behalf.

LIVE

Human review before publish

The admin/implementation workflow keeps extracted or entered client information in review until a human validates what should be published.

LIVE

Role separation

Agent, Supervisor/Trainer, and Admin/Implementation views separate frontline use, coaching/testing, and profile configuration.

LIVE

Session expiration

Private evaluator sessions expire after twelve hours. Invitation links expire after seven days.

LIVE

HTTPS delivery

The current hosted demo and Deal Room are served over HTTPS. Session tokens are stored server-side by hash rather than plaintext.

Pre-production security gate

When can proprietary production data enter Agent First?

Not before the Security Readiness Gate. Agent First can be demonstrated, configured, benchmarked, and tested with fictional or appropriately de-identified material. Before a real production pilot accepts proprietary operating procedures, client-specific production material, sensitive production context, or regulated information, an experienced security-minded SaaS engineer or application-security consultant reviews the actual architecture; critical findings are remediated; tenant/role isolation and data handling are retested; and permitted/prohibited data categories are documented.

Review

Threat model + architecture/data-flow map; authentication/sessions; server-side RBAC/tenant isolation; APIs/database; secrets; uploads; AI-provider flow; logs; backups; dependencies; retention/deletion; incident response.

Verify

Map technical controls against OWASP ASVS 5.0, prioritize OWASP Top 10 risks such as Broken Access Control, and use NIST SSDF as a secure-development framework.

Remediate

Fix or explicitly risk-accept critical/high findings with reviewer involvement before the production-pilot gate is signed off.

Governance

Who can decide what a rule means?

Client rule owner

Approves policy meaning, exceptions, required wording, routing, and changes. Ambiguity returns to this person rather than being guessed by Agent First.

Agent First implementation

Structures approved material into the client profile, flags conflicts or gaps, tests the configured behavior, and documents changes.

Frontline user

Uses the surfaced guidance and retains responsibility for the human action. The interface should make next steps and sources inspectable.

Not claimed: Agent First is not currently presented as SOC 2 certified, HIPAA certified, PCI certified, or as having completed an enterprise security audit. The immediate requirement is the pre-production security architecture/application-security review and remediation gate. Formal compliance work follows only when the target buyer or regulated use case actually requires it.
Buyer FAQ

Questions we expect before a pilot

Does the AI make the policy decision?

No. The organization supplies and approves the rules. AI/software can help resolve context and generate what the worker sees, but the system is not authorized to invent organizational policy.

Do we need an integration before we can pilot?

The preferred first pilot is configuration-first and bounded. We choose a workflow that can be tested with approved source material before requiring a major system integration.

What information do you need from us?

A defined workflow, approved source material, a rule owner, representative users, a supervisor/sponsor, and enough baseline or controlled-test access to measure the agreed hypotheses.

Can we restrict what evaluators see?

Yes. The private environment supports invited accounts, role-aware views, and permission-gated Deal Room materials. More granular enterprise authorization can be added as the deployment matures.

What happens if two source documents conflict?

The conflict is flagged for the designated client rule owner. Agent First should not silently choose which organizational rule is “right.”

Can we use fictional data before the production pilot?

Yes. That is the preferred path while security readiness work is underway. Controlled scenarios and de-identified material can establish speed, accuracy, navigation burden, usability, and configuration quality without introducing proprietary production information prematurely.

How are passwords handled today?

The private evaluator account stores a salted PBKDF2 password hash rather than plaintext. Sessions use random opaque tokens; the server stores only token hashes and expires sessions after twelve hours. The security review will independently verify the authentication/session implementation and define the password-reset/MFA/SSO path required for production.

What must happen before proprietary production data is accepted?

Agent First's Security Readiness Gate requires an experienced security-minded SaaS engineer/application-security consultant to review the actual architecture and threat model; test authentication, sessions, server-side authorization and tenant isolation; review APIs, database access, secrets, uploads, logging, backups, dependencies, retention/deletion, model-provider data flows and incident response; map against OWASP ASVS 5.0; remediate critical findings; and document the allowed pilot data boundary before sign-off.
