How it decides

Not a document to search. A live authorization.

A knowledge base answers where a policy lives. Agent First answers a narrower question: given this client, this customer, this request, and this moment, what should the agent do right now? Every answer resolves to one of nine plain outcomes, not a paragraph to interpret.

ALLOW / DO NOT ALLOW
Whether the agent can proceed on their own, no one else needed.
VERIFY
A detail to confirm before deciding anything else.
DISCLOSE
A specific line this client requires the agent to say out loud.
TRANSFER / ESCALATE
When the call, or the decision, belongs with someone else.
DOCUMENT / INTERNAL NOTE
What gets recorded for whoever handles this next.
SAY TO CUSTOMER / NEXT ACTION
The exact words for this moment, and what happens the second the call ends.

Inside one industry, adding a client is genuinely configuration: its real rules entered once into a structured Client Profile, running on the same engine already live today. What this could look like elsewhere

Same question, same engine, two different clients, two different correct answers.

The four examples below are illustrative. The companies are not real and the rules are not verified against how these industries actually operate today. They exist to show what a second industry could look like, not to claim it has already been built.

Insurance
Same call: a minor accident, no injuries, asking about a rental car.
One client's profile lets the agent approve a rental on the spot, up to a daily cap. Another requires verifying a coverage add-on first, then escalating to an adjuster before any dollar amount is promised.
Healthcare
Same call: a parent asking for a same-day visit for a mild fever.
One client's profile lets the agent book directly against a defined list of non-urgent symptoms. Another sends every same-day sick call to nurse triage first, no exceptions.
Home services
Same call: no hot water, reported at 9:40pm.
One client's profile treats it as an after-hours emergency and dispatches a tech tonight. Another holds it for the next available slot, unless the caller describes active water damage.
Property management
Same call: no heat, 38°F outside, reported at 11pm.
One client's profile authorizes the agent to dispatch the on-call vendor directly. Another never lets an agent dispatch anyone; every after-hours emergency gets escalated to a live manager.

Questions

A few things people ask first.

Does this replace agents?
No. The agent stays on every call and has the final word every time. Agent First hands them a decision and the exact words to say. It does not talk to the customer and it is not a chatbot.
What does setup look like for a new client?
A client's real rules get entered once into a structured Client Profile. It is a configuration process, not a software build, though the time it takes depends on how many exceptions that client's real rules actually have.
What happens to a client's rules once they're entered?
Each client's Client Profile is its own configuration. One client's rules are never visible in another client's calls, even when the same agent works both.
Does this work outside the industry it's live in today?
The architecture is built to extend across industries, and the examples above show what that could look like. Today, the proven decision logic runs live in one industry. Reaching that same depth in a new industry is the direction, not a finished claim.
Are you looking for pilot partners?
Yes. The Starter tier above is built for exactly that: a single-client pilot to test Agent First against real rules and real calls before deciding whether to expand further.
How is this different from a script or a knowledge base?
A knowledge base tells an agent where a policy lives. Agent First resolves that policy into one specific answer for this client, this customer, and this moment, instead of leaving the agent to interpret it live.
