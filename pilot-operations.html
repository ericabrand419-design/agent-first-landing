Operating rule: A pilot is accepted only when there is a bounded workflow, approved source material, a decision owner, frontline access, and a credible way to establish the baseline. This package should reduce ambiguity, not create paperwork for its own sake.
INTERNAL

1. Pilot Qualification Scorecard

100-point gate with six hard-stop conditions. Accept at 75+ only with no hard stop; 60-74 is conditional; below 60 or any hard stop is no-go.

DecisionRule
GO75-100 + no hard stop
CONDITIONAL60-74 + no hard stop; resolve named gaps before commitment
NO-GOBelow 60 or any hard stop

10. Responsibilities Matrix

Clear split between Agent First configuration/support responsibilities and customer policy ownership, validation, user access, source/data authorization, and commercial decisions.

SHARED

11. Baseline Measurement Plan

Operational definitions and evidence sources for decision resolution time, correct-client rule application, first-contact accuracy, supervisor pull-ins, and new-hire ramp time.

SHARED

12. Pilot Test Plan

T0 baseline test, T1 pre-launch product test, live pilot, T2 midpoint check, T3 final controlled test, and final evidence review.

SHARED

13. Success Metrics / Scorecard

Default kickoff targets: 20% faster decision resolution; >=95% correct-client rule application or meaningful improvement; +10-point first-contact accuracy; 25% fewer pull-ins; 20% faster ramp where applicable.

SHARED

14. Agent / User Testing Protocol

Five-minute timed performance test drawn from a ~20-minute scenario pool, using real product language, client switching, hidden answer keys, and post-test usability/trust pulse.

SHARED

15. Supervisor Feedback Process

Ongoing gap log plus weekly/biweekly prompts focused on pull-ins, awkward guidance, rule changes, independence, and workflow effects.

SHARED

16. Weekly Pilot Review Template

Nine-item meeting: usage, metric pulse, rule changes, issues, agent feedback, supervisor feedback, scope control, decisions, and next week.

SHARED

17. Issue / Escalation Process

S0 stop, S1 critical rule defect, S2 usability/workflow defect, S3 enhancement. Critical correctness/security/compliance issues are handled separately from feature requests.

SHARED

18. Final Pilot Report Template

Executive decision, scope, baseline, implementation, metrics, controlled tests, operational evidence, feedback, limitations, learnings, recommendation, and case-study decision.

19. Case-Study Permission Language

Opt-in only after results; named public, anonymized public, private reference, or no external use. Specific draft approval required before publication.

Legal review required. This is a business drafting framework, not final legal language.

20. Pilot-to-Subscription Conversion Proposal

Carry forward the validated Profile and propose the next deployment from the evidence. Expansion may add workflows, profiles, locations, integrations, users, or support. No continuation is automatic.

SHARED

21. Pilot Pricing

Founding Design Partner assumption: $5,000 for an approximately six-week bounded pilot, one workflow family, up to three configured profiles/locations, and up to 20 frontline users. Major integrations or additional scope are separately priced.

22. Implementation / Configuration Assumptions

One primary Profile, one bounded workflow, approved sources and validator, no major integration required to prove core value, named users/supervisors, measurable baseline, versioned rule changes.

SHARED

23. Subscription Pricing Assumptions

Working subscription assumptions are finalized only after pilot evidence and deployment scope are known. Internal modeling may use a small-deployment starting hypothesis around $1,500/month; this is not a contractual or published renewal commitment.

24. Pilot Agreement / SOW Template

Business SOW skeleton covering scope, term, fees, responsibilities, measurement, data/security, rule authority, changes, suspension, final report, continuation, and case-study treatment. Counsel must adapt before use.

Legal review required. This is a business drafting framework, not final legal language.

25. Basic Security / Data Information

Data minimization, organizational rule authority, role separation, authorized recordings/transcripts only, rule-change governance, and explicit confirmation required for hosting, retention, subprocessors, encryption, and regulated data.

Before sending a formal security packet: verify hosting provider(s), model provider(s), storage, encryption in transit/at rest, subprocessors, and retention from the production architecture. Do not claim SOC 2, HIPAA, ISO, PCI, or similar status unless actually achieved and applicable.
